# AUGUST SHOP サイト 運用ガイド

買取実績・クーポン・取扱ブランドは、**HTMLを触らずに `data/` フォルダのファイルを書き換えるだけ**で更新できます。
すべて GitHub の Web 画面だけで完結します。保存（Commit）してから1〜2分でサイトに反映されます。

| 更新したいもの | 編集するファイル | 画像を置く場所 |
|---|---|---|
| 買取実績 | `data/results.json` | `assets/img/results/` |
| クーポン | `data/coupons.json` | `assets/img/coupons/`（任意） |
| 取扱ブランド | `data/brands.json` | なし |
| LINE ID・住所・許可番号・フォーム送信先など | `assets/js/config.js` | なし |

---

## GitHub でファイルを編集する基本操作

1. GitHub でリポジトリを開き、編集したいファイル（例：`data/results.json`）をクリック
2. 右上の **鉛筆アイコン（Edit this file）** をクリック
3. 内容を書き換える
4. 右上の **「Commit changes…」** → メッセージ（例：「買取実績を追加」）→ **「Commit changes」**

### 画像をアップロードする

1. GitHub で `assets/img/results/` フォルダを開く
2. 右上の **「Add file」→「Upload files」**
3. 画像をドラッグ＆ドロップ → **「Commit changes」**

> 画像のファイル名は **半角英数字とハイフンだけ** にしてください（例：`2026-10-12-levis-501.jpg`）。日本語や空白は避けます。
> スマホの写真はそのままだと大きいので、長辺1200px程度・縦長（4:5）に切り抜いてから上げると表示が速く、きれいに揃います。

## 1. 買取実績を1件追加する

**手順**

1. 商品写真を `assets/img/results/` にアップロード（上の手順）
2. `data/results.json` を編集し、**先頭の `[` のすぐ下**に次のブロックを貼り付けて値を書き換える

```json
  {
    "date": "2026-10-12",
    "brand": "Levi's",
    "item": "501 66前期",
    "size": "W32",
    "condition": "使用感あり",
    "price": 38000,
    "image": "results/2026-10-12-levis-501.jpg"
  },
```

| 項目 | 書き方 |
|---|---|
| `date` | 買取日。`2026-10-12` の形 |
| `brand` | ブランド名。実績ページの絞り込みボタンに使われます。**同じブランドは毎回同じ綴り**で |
| `item` | アイテム名・品番（空 `""` でも可） |
| `size` / `condition` | サイズ・状態（空 `""` でも可） |
| `price` | 買取価格。**数字だけ**（`38000`）。`¥` やカンマは表示時に自動でつきます |
| `image` | `results/` ＋ アップロードしたファイル名。画像がなければ `""`（ブランド名だけの枠になります） |

- 表示順は `date` の **新しい順に自動で並びます**。ファイル内の順番は気にしなくて大丈夫です
- トップページには最新10件、実績ページには全件が表示されます

### 買取実績を削除する

`{` から `},` までのブロックを丸ごと消します。不要になった画像も `assets/img/results/` から削除してください（ファイルを開いて右上の「…」→「Delete file」）。

### ダミーデータを本番データに入れ替えるとき（おすすめの進め方）

現在入っている12件は **サンプル**（アイテム名に「（サンプル）」と付いたもの）です。

1. **最初の1回だけ**：`data/results.json` の中身を `[]` だけにして、サンプル画像（`assets/img/results/` の中身）を削除
2. 本番の実績を1件ずつ上の手順で追加（最初は5〜10件あるとトップがきれいに埋まります）
3. 以降は、買取があるたびに **写真を上げる → 1ブロック追記** の繰り返し

**楽に続けるコツ**

- 撮影時に「全体1枚」を同じ背景・同じ向きで撮ると、一覧が揃って見栄えが良くなります
- 毎回すべてを載せる必要はありません。**週に1回、目を引くものを2〜3件まとめて**追加するくらいが続けやすいです
- 件数が増えすぎたら、古いものは削除して構いません（実績ページは12件ずつ表示されます）
- 0件にしても「買取実績は準備中です」と表示され、ページは崩れません

## 2. クーポンを追加する・終了する

`data/coupons.json` を編集します。

### 追加する

既存のクーポンのブロック（`{` 〜 `},`）を1つコピーして貼り付け、値を書き換えます。

```json
  {
    "id": "WINTER10",
    "title": "冬物買取 10%UP",
    "rate": "10%UP",
    "description": "アウター・ニットの買取価格を10%アップします。",
    "notes": ["2026年1月31日まで", "他クーポンとの併用不可"],
    "image": "",
    "start": "2026-12-01",
    "end": "2027-01-31",
    "featured": false,
    "active": true
  },
```

| 項目 | 書き方 |
|---|---|
| `id` | クーポンID。半角英数字（LINEで伝えてもらう、シートに記録される名前）。**他と重複させない** |
| `title` | クーポン名 |
| `rate` | 大きく表示される文字（`20%UP`、`500円UP` など） |
| `description` | 説明文 |
| `notes` | 注意書き。`["…", "…"]` の形。なければ `[]` |
| `image` | 画像を使う場合は `coupons/ファイル名.jpg`。なければ `""`（文字だけのデザインになります） |
| `start` | 表示開始日。空 `""` なら即日 |
| `end` | 終了日（この日まで表示）。空 `""` なら無期限 |
| `featured` | `true` にすると一番大きく目立つデザインで表示。**1つだけ** `true` にしてください |
| `active` | `false` にすると即座に非表示 |

### 終了する

- **期限で自動終了**：`end` に日付を入れておけば、翌日から自動で消えます
- **すぐ止める**：`"active": false` に変更

終了したクーポンはファイルに残しておいても表示されません（現在入っている「【表示されない例】」の2件がその見本です。不要なら削除して構いません）。

クーポンは、トップページ・買取ページの一覧と、買取フォームの「利用するクーポン」の選択肢に、自動で反映されます。

## 3. 取扱ブランドを追加する

`data/brands.json` に1行追加します。どこに書いても、一覧ページではアルファベット順に並びます。

```json
  { "name": "Barbour", "kana": "バブアー", "marquee": 0 },
```

| 項目 | 書き方 |
|---|---|
| `name` | ブランド名 |
| `kana` | 読み（空 `""` でも可） |
| `marquee` | トップの流れる帯に出すか。`1`＝上段、`2`＝下段、`0`＝出さない（一覧ページのみ） |

---

## 4. 店舗情報・LINE・送信先を変える

`assets/js/config.js` を編集します。`"…"` の中を書き換えるだけで、全ページに反映されます。

- `lineId`：LINE ID、`lineUrl`：友だち追加URL（入れると買取ページに「LINEで友だち追加」ボタンが出ます）
- `address` / `access` / `payment` / `license` / `buyMail`：住所・アクセス・決済方法・古物商許可番号・買取専用メール
- `formEndpoint`：買取フォームの送信先（[GASデプロイ手順.md](GASデプロイ手順.md) を参照）

> トップページ下部の検索エンジン向け情報（`index.html` の `"streetAddress":"[住所を差し込み]"`）だけは HTML に直接書かれています。住所が決まったら、ここも書き換えてください。

## よくあるミスと確認方法

JSON は記号1つの間違いで **そのファイルの内容がすべて表示されなくなります**（ページは崩れず「読み込めませんでした」と出ます）。

| ミス | 正しい書き方 |
|---|---|
| ブロックの間の **カンマ忘れ** | `}` と次の `{` の間に `,` が必要 → `},` |
| **最後のブロックの後ろにカンマ** | 最後のブロックだけは `}` で終わる（`},` にしない）→ その後に `]` |
| 全角の `“ ”` や `，` | 記号はすべて **半角**（`"` `,` `:`） |
| 価格に `¥` やカンマ | `"price": 38000`（数字のみ、`"` で囲まない） |
| `true` / `false` を `"true"` と書く | `"featured": true`（`"` で囲まない） |
| 画像のファイル名違い | `image` の綴り・拡張子（`.jpg` / `.JPG`）がアップロードしたファイルと完全に一致しているか |
| Levi's の `'` | そのままでOK（`"Levi's"`）。`"` を含めたいときだけ `\"` と書く |

### 確認方法

1. **保存前**：編集した内容をすべてコピーし、<https://jsonlint.com/> に貼り付けて「Validate JSON」。緑の「Valid JSON」ならOK
2. **保存後**：GitHub の「Actions」タブ、またはコミット横のマークを確認。データのチェックが自動で走り、**緑のチェック ✓** ならOK、**赤い ✕** ならどこが間違っているかが表示されます
3. **サイトで確認**：1〜2分後にページを開き、表示を確認（変わらなければ、ブラウザを再読み込み）

困ったときは、GitHub のファイル画面右上の「History」から、1つ前の状態に戻せます。
